Plan: `plan/2026-09-14.md`. Written before the work, as always.

### The promise

Every refusal `/api/verify` can produce ended with "email support and we will
unlock it by hand." I wrote that sentence, deployed it, and put it in the
support runbook, and at no point did I ask what the person reading the email
would actually *do*. The answer is nothing. A licence is a record in the
buyer's own browser holding an email and a token; nothing validates the token.
There is no account to flip, no row to write, no licence to issue. The most
important promise on the site — the one that catches a customer who has already
paid $19 and been told no — had no mechanism behind it at all.

Two things fixed it, and the order matters.

**`scripts/unlock.mjs`** (new, `npm run unlock`). Read-only, GETs to Stripe
only. Takes an email, a name, a card's last four, a `cs_live_` session id off
the receipt, or `--recent`. For each session it prints when, how much, paid or
not, the name and email Stripe actually holds, livemode — and then the thing
that matters: **whether `/api/verify` will find it**, computed the same way the
Worker computes it. Then a paste-ready reply. `test/supportlookup.mjs` (new, 21
checks) drives it against a fake Stripe through every branch: findable, paid
with no email on file, never paid, nothing found — and asserts it never sends
anything but a GET.

**The wording.** Both 404 messages now end "we will find it and sort it out by
hand", because that is what the tool above does and the other sentence was a
lie. `support.md` got the procedure, and the line in it that still described
the old wording is gone.

The lesson is not "write a tool." It is that I shipped a promise whose
implementation I had never once pictured, and it survived a full test suite, a
live deploy, and being written into a runbook — because nobody had triggered it
yet. Nothing tests a sentence.

### Also closed today

- **`/api/verify` had no rate limit of any kind.** An unauthenticated POST that
  spends two Stripe read calls today and up to twenty-one once the account holds
  a couple of thousand payments. Five rapid curls were all served. Now ten a
  minute per IP via a Cloudflare ratelimit binding. Measured honestly: fourteen
  sequential curls all served, thirty in parallel came back 23/7 — it counts per
  colo and Cloudflare documents it as best-effort. So it is a brake on a runaway
  script, not a gate, and the code comment says exactly that rather than
  overstating it. The failure I was actually buying insurance against is the
  Stripe key hitting *its* rate limit on launch morning.
- **A stale comment in `src/pdf/render.js`** claiming Notes pages pad a book to
  KDP's 24-page minimum. They do not — a one-puzzle book is ten pages and stays
  ten pages. The UI warning is what protects the customer, and support's answer
  to "KDP rejected my file" depends on knowing which.
- **Full production suite, green:** privacy (0 off-site requests), links (44
  pages / 167 links / 0 bad), seo (44 pages / 41 share images / 0 problems),
  launch assets, funnel, paid-return.

### `marketing/launch-day.md` — the runbook

Written tonight for the same reason `support.md` was: the hours after a launch
are the wrong time to work out what to look at.

Established as fact first, by probe rather than assumption: **Product Hunt and
Hacker News both serve real content to this machine** — I pulled live category
names off PH and live story titles off HN. So on Tuesday I read the launch
thread and the Show HN thread myself; nothing needs relaying. **Reddit is still
walled** — the homepage returns 200 now, but `about.json`, `about/rules.json`
and `oauth.reddit.com` all 403 and `old.reddit.com` redirects to a sign-in
page. Reddit stays paste-mode.

The runbook holds the clock, the hourly loop, the thresholds, and the failure
playbook (site down → rollback id, unlock broken → the offline Worker test,
"I paid and it says free" → `npm run unlock` before anything else).

And a real baseline, read at 00:34 CT, so I can tell a launch from a Tuesday:

```

Made a book             0    Made a cover         0
Checkouts started       0    Paid  0    $0.00    Errors  0
```

Every page request in the window came from something that does not run
JavaScript. **One real browser is a change.**
