# 2026-09-15 — launch day

Product Hunt goes live 12:01am PT / 2:01am CT. Written the day before, because
the hours after a launch are the wrong time to decide anything.

The runbook is `marketing/launch-day.md` and it is the operational
document — clock, hourly loop, thresholds, failure playbook. This file is the
plan: what I intend, so that tomorrow's `actual/` can be honest about the gap.

## What I am not doing

**No deploys.** The site is frozen as of tonight unless something is broken for
real users. A launch day is the worst possible day to change code: I cannot
tell a bug I introduced from a bug traffic revealed, and every minute spent
diagnosing is a minute not spent answering somebody. If a fix is genuinely
needed, roll back first (`cacf2b59-0587-4427-934b-ed30702c5561`) and think
second. The runbook holds the live id; if the two ever disagree, the runbook is
right, because that is the file I update at the terminal.

**No new features, however good the suggestion.** Somebody will ask for a
puzzle type we do not have and I will want to build it by lunchtime. Write it
down instead. Two people asking for the same thing is the best signal I will
ever get about what to build next, and it keeps until Thursday.

**No arguing.** Correct a factual error once, with a fact, and stop.

## What I am doing

1. **Watching the funnel hourly** — `npm run traffic 2`, read against the cold
   baseline in the runbook (13 page requests, 0 real browsers, $0). One real
   browser is a change. The line that is money is checkouts paid; everything
   above it is only interesting because it explains that one.
2. **Reading the Product Hunt thread myself** — I verified I can. I need the
   link from the boss the moment it is scheduled, and I have asked twice.
3. **Drafting every reply within minutes, for the boss to paste.** Answers to
   the likely questions are already written in `product-hunt.md`; the job
   tomorrow is the unlikely ones.
4. **Support first, always.** Any "I paid and it says free" outranks everything
   above. `npm run unlock -- <email>` before I reply, not after.

## What success looks like, stated in advance so I cannot move it

The goal of this whole project is a stranger paying. Product Hunt is one of five
channels and not obviously the best one; a good outcome is not a number of
upvotes.

- **The floor:** the site stays up, nobody who arrives is blocked by a bug, and
  every question gets an honest answer the same day.
- **The real result:** one stranger pays $19. That has never happened. If it
  happens tomorrow, the thing this project set out to prove is proved, and
  everything after is scale.
- **The likely result:** some traffic, some books made, no sales. That is not
  failure — it is the free tier doing exactly what it was designed to do, and
  the interesting number becomes how many people made a whole book and still
  did not pay, because that tells me whether $19 is the problem or the
  watermark is not annoying enough.

Whatever happens, `actual/2026-09-15.md` gets the real numbers, including the
zeroes, and especially the zeroes.
