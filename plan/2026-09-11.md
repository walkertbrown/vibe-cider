# Plan — 2026-09-11

## Phase 31 plan — the YouTube video

The boss opened a YouTube channel under the studio name and connected it to
Buffer. A channel with no video is nothing, and the Product Hunt launch on
Tuesday has a video slot in the gallery that is empty.

**What:** one recording, 60–90 seconds, of the real app making a real book,
no narration, captions on screen, ending on pages from the PDF it just made
and the cover. No mock-ups, no speeding up the generation — if the book takes
eight seconds to render, the video shows eight seconds.

**How:** Playwright's `recordVideo` against the workers.dev host (so my run
does not land in the real domain's analytics). Playwright ships its own
ffmpeg, which is what writes the WebM — so the "no ffmpeg" gap is not a gap
for recording. Whether Buffer's YouTube upload accepts WebM I do not know;
try it, and if it refuses, fetch a static ffmpeg build into the scratchpad
and transcode to H.264 MP4. Host the file under `public/`, since Buffer
fetches media by URL.

**Then:** draft (not queue) a Buffer YouTube post with a searchable title,
a description that links the guide and the tool, and the right category.
Same rule as Pinterest — the boss looks before the studio's first video goes
public.

**Also:** embed it on the landing page if it is better than the GIF, and put
the URL in the launch file for the gallery.

Needs from boss: a look at the draft in Buffer, then one click.

## Phase 33 plan — one landing page per puzzle type

The site has one front door aimed at "KDP puzzle book". Buyers search for
the type: "sudoku book generator", "maze generator for KDP", "word search
book maker". One page cannot rank for three different queries, and the
Pinterest pins are already aimed at those three audiences with nowhere
specific to land.

**Build:** `/word-search-book-generator`, `/sudoku-book-generator`,
`/maze-book-generator`. Each: a headline for that search; what that type's
buyer actually worries about (words appearing twice / a sudoku with two
answers / a maze with two routes) and what the tool does about it, with the
real figures from the code; that type's sample PDF; page-count and print-cost
table for that type; a button that opens the tool with the type already
chosen. That last part needs the tool to read `?kind=` from the URL — small
change to `main.js`, covered by a live test. Sitemap, header links, JSON-LD.

**Not:** three copies of the landing page with a word swapped. If a section
would be the same on all three, it belongs on the guide and gets linked.

Needs from boss: nothing.
